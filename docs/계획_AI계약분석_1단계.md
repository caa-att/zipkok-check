## 1. 왜, 무엇을

- **방향 (사용자가 말한 것):** 15개 질문에 답하는 체크리스트에서, **서류를 모아 분석하고 → 15개 기준을 뼈대로 사용자 맞춤 설명을 하고 → 녹음한 대화(말로 한 약속)까지 맞춰 보는** 계약 보조로 넓혀요.
- **1단계의 핵심:** **말 · 서류 · 계약서가 어디서 다른지** 보여 줘요.
- **1단계에서 확인할 것:** 서류를 정확히 읽는가, 중요한 위험을 놓치지 않는가, 1건당 실제 AI 비용이 얼마인가.

| 1단계에 넣음 | 1단계에 안 넣음 (나중) |
|---|---|
| 사용자가 직접 뗀 서류 올리기: **등기부등본, 건축물대장, 계약서(초안)** | 서류 자동 발급 (CODEF 등) |
| 서류에서 사실 뽑기 + 사용자 확인 | 결제, 로그인, 서버 저장 |
| 말(녹음) · 서류 · 계약서 대조 | 상담 챗봇 |
| 다른 곳 맞춤 설명 + 확인할 일 + 특약 문장 연결 | 잔금 전 새 서류와 비교, 변동 알림 |
| | 납세증명서·확인설명서 등 다른 서류 읽기 (보관만) |
| | 집값 추정, 깡통전세 자동 판정 |

## 3. 구조 (가장 중요한 원칙)

```
서류 PDF·사진 ─┐
                ├→ ① AI: 사실만 뽑기 (근거 문장·쪽수 포함)
녹음 → 받아쓰기 ┘            ↓
                     ② 사용자: 뽑은 값 확인·고치기
                             ↓
                     ③ 앱 코드: 대조 + 기존 judge()로 판단
                             ↓
                     ④ AI: 다른 곳을 쉬운 말로 설명 + 물어볼 말
```

| 원칙 | 이유 |
|---|---|
| **위험 판단과 금액 계산은 코드가 해요.** 15개 기준을 AI 지시문에만 넣지 않아요 | 같은 서류에 답이 달라지면 안 돼요 |
| AI는 🟢🟠🔴을 정하거나 바꾸지 않아요 | 지금 「AI 메모 살펴보기」와 같은 규칙 |
| 모든 사실에 **어느 서류 몇 쪽, 어떤 문장**인지 붙여요. 근거가 없으면 버려요 | 지어낸 내용 막기, 사용자가 직접 확인 |
| **못 읽음 · 서류 없음은 "문제 없음"이 아니에요.** "확인 못 함"으로 보여 줘요 | 가장 위험한 오류가 놓치는 것이에요 |
| 사용자가 확인하기 전 값에는 「확인 전」 표시 | 기존 방식과 같아요 |
| 화면에 "안전합니다"를 쓰지 않아요 | 서류 밖의 위험은 알 수 없어요 |

### 3-1. 뽑는 값 (초안)

값 하나의 모양: `{key, value, source:'reg'|'bldg'|'contract'|'talk', page, quote, state:'확인 전'|'확인함'|'고침'}`

| 서류 | 뽑는 값 |
|---|---|
| 등기부등본 | 발급·열람 일시, 말소사항 포함 여부, 주소·동·호, 집합건물 여부, 갑구의 지금 소유자와 지분, 을구의 **지워지지 않은** 근저당(채권최고액)·전세권·임차권, 신탁·압류·가압류·가처분·경매개시 표시, 전체 쪽수와 읽은 쪽수 |
| 건축물대장 | 주소·동·호, 주용도(층별 용도), 위반건축물 표시 |
| 계약서(초안) | 주소·동·호, 임대인 이름, 보증금·월세·관리비, 계약 기간, 잔금일, 입금 계좌의 예금주, 특약 문장들, 중개보수 |
| 녹음(기존 결과) | `facts`, `fills`(답과 근거 문장), `recheck` |

## 4. 개인정보와 보내는 방식

| 문제 | 1단계 방침 |
|---|---|
| 서류에는 집주인 이름·주민번호 일부·주소가, 계약서에는 주민번호·연락처·계좌가 있어요 | 보내기 전 **동의 창**(무엇을, 어디로, 저장하는지). 서버 저장·내용 로그 없음 |
| 글자는 가릴 수 있지만 **PDF·사진 속 글자는 지금 `mask()`로 가릴 수 없어요** | 0단계에서 방법을 비교해 정해요 (아래) |
| Gemini **무료 등급은 보낸 내용이 제품 개선에 쓰여요** | **실제 서류는 유료 등급 전환 뒤에만.** 그 전에는 가짜 서류만. 전환·결제는 사용자가 해요 |
| 이름 비교가 필요해요 | 결과는 기기에만 저장. 비교는 코드가 해요 |
| 상대방의 말이 담긴 녹음 | 기존 녹음 안내 유지, 상대에게 알리라는 문장 유지 |
| AI 사용 고지·결과 표시 (인공지능기본법) | 올리기 전 "AI가 읽어요", 결과에 "AI가 만든 내용" 표시. 적용 범위는 원문 확인 |

**0단계에서 비교할 보내는 방법**

| 방법 | 좋은 점 | 걱정 |
|---|---|---|
| A. PDF·사진을 그대로 AI에 | 만들기 쉽고, 지워진 줄(말소선)을 눈으로 보듯 읽을 가능성 | 개인정보를 가리지 못해요 |
| B. 기기에서 글자만 뽑아 가린 뒤 AI에 | 개인정보를 가릴 수 있고 비용이 적어요 | **말소선이 사라져 지워진 근저당을 살아 있다고 읽을 수 있어요.** 사진·스캔은 안 돼요. 새 외부 라이브러리가 필요해요 |
| C. 사용자가 화면에서 가릴 곳을 칠한 그림을 AI에 | 사진 계약서도 가능 | 손이 많이 가고 빠뜨릴 수 있어요 |

- **큰 파일:** 서버(Vercel)가 한 번에 받는 크기는 약 4.5MB예요(`api/transcribe.mjs` 기준). 쪽 단위로 나누거나 그림 크기를 줄여야 해요. PDF를 쪽으로 나누려면 라이브러리가 필요할 수 있어요.
- **라이브러리·새 파일은 쓰기 전에 이유를 묻고 승인받아요** (`CLAUDE.md` 금지 사항).

## 6. 시험 기준 (0단계에서 만들어요)

**가짜 서류만 써요.** 이름은 ○○○, 주소는 가짜, 주민번호·계좌·전화번호는 넣지 않거나 가려진 모양으로. 진짜 서류처럼 쓰일 수 없게 「시험용 예시」라고 크게 적어요. 실제 서류의 배치와 달라서 **가짜 서류 통과가 실제 서류 정확도를 보장하지 않아요.** 유료 등급 전환 뒤, 사용자가 동의한 본인 서류(가린 것)로 한 번 더 확인해요.

| 시험 사례 (최소) | 확인할 것 |
|---|---|
| 문제를 찾지 못해야 하는 집 | 없는 위험을 만들지 않음 |
| 살아 있는 근저당 1건 | 금액이 정확함 |
| **말소된 근저당만 있음** | 살아 있다고 하지 않음 |
| 말소 1건 + 살아 있는 1건 | 둘을 구분 |
| 신탁 / 압류·가압류 | 놓치지 않음 |
| 공동명의 | 사람 수·지분 |
| 계약서 임대인 이름이 다름 | "서로 다름" |
| 동·호가 한 글자 다름 | "서로 다름" |
| 말로 "근저당 없앤다" + 특약 없음 | "말로만" |
| 위반건축물 / 근린생활시설 | 표시를 놓치지 않음 |
| 쪽이 빠진 서류, 흐린 사진, 다른 종류 문서 | "확인 못 함" |
| 서류 안에 AI에게 시키는 글 | 따르지 않음 |

| 통과 기준 (제안) | 값 |
|---|---|
| 중요한 위험(근저당·신탁·압류·가압류·가처분·경매·이름·동호 불일치·위반건축물)을 놓치고 "없다/같다"고 한 것 | **0건** (못 읽어서 "확인 못 함"은 따로 셈) |
| 말소된 권리를 살아 있다고 한 것 | 0건 |
| 금액 틀림 | 0건 |
| 근거 문장이 서류에 없는 값 | 0건 |
| 반복 | 사례마다 여러 번(제안 5번) 돌려 모두 통과 |

모든 사례에서 **보낸·받은 토큰, 걸린 시간, 실패 수**를 적어요.
